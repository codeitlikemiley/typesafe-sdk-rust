# Audit 2026-09-24

Client-only crate. Callers set a base URL and use the same System One contract (`POST /v1/systemone`, `GET /v1/models`) against their own server. No OpenAI facade. No server in this crate.

Evidence labels: **measured** (ran it or read this repo / a cited file), **inferred** (follows from that evidence), **guess** (not checked).

## Verdict

The override already existed. `ClientBuilder::base_url` and `TYPESAFE_BASE_URL` replace `https://api.typesafe.ai`. `system_one` and `models` both append to that string. This PR makes that path obvious and rejects a blank or non-http(s) base URL at `build`. The contract test locks `/gateway`. The example mounts plain `/v1/…` on the mock origin.

Do not add a typed profile, a feature flag, or an HTTP server. The mechanism is one string.

## What already worked

**Measured** in `src/config.rs`, `src/client.rs`, `src/request.rs`, `src/blocking.rs`.

| Piece | Behavior |
| --- | --- |
| Default host | `DEFAULT_BASE_URL` = `https://api.typesafe.ai` |
| Override | Builder `base_url` wins. If omitted, `TYPESAFE_BASE_URL`. Blank env is ignored and the default is used. |
| Join | `format!("{}{path}", base_url)` with `/v1/systemone` and `/v1/models`. Same `Config` for both calls. |
| Slash | Trailing `/` stripped before this PR (`trim_end_matches`). Still stripped, now after trim, and tested. |
| Auth | `Authorization: Bearer <api_key>` is set after user headers, so it always wins. |
| Extra headers | `x-typesafe-sdk`, `x-typesafe-runtime`, `user-agent: typesafe-sdk/<version>`. `x-typesafe-retry-count` only on retries. |
| Request id | Read from `x-typesafe-request-id` when present. Absent is not an error on the happy path. |
| Model | Default `jev-latest`, override via `model`, `TYPESAFE_DEFAULT_MODEL`, or per-call `SystemOneOpts.model`. |
| TLS | `reqwest` with `rustls-tls` only. Custom CA or proxy: pass `http_client`. |
| Redirects | Default `reqwest` 0.11.27 policy follows up to 10 hops (`Policy::limited(10)` in that crate). Cross-host redirects drop `Authorization`. |
| Blocking | `blocking::Builder::base_url` forwards to the async builder. |

**Measured** sibling, Python `typesafe-sdk` 0.6.0 `src/typesafe_sdk/_core/config.py`: `base_url` or `TYPESAFE_BASE_URL`, then `rstrip("/")`, then `base_url + path` in `transport.py`. Paths are the same two constants. Auth is Bearer. This Rust crate already matched that shape.

**Measured** published consumer, not called from this VM: [OpenRouter TypeSafe SDK guide](https://openrouter.ai/docs/guides/community/typesafe-sdk) tells callers to set `base_url` to `https://openrouter.ai/api` so the SDK posts to `https://openrouter.ai/api/v1/systemone`. That is the same pattern. This audit did not send a live request there.

## What was missing

**Measured** before this PR: README listed `TYPESAFE_BASE_URL`. `AGENTS.md` did not. No example showed `.base_url(...)`. No test locked a path prefix or a bad URL. A blank builder URL became a relative request at send time.

**Inferred** gaps that are not bugs if the other server speaks System One:

- Bearer cannot be replaced without a custom `http_client` that the SDK then overwrites anyway. `prepare` writes `Authorization` last.
- `GET /v1/models` requires `name`, `description`, and `release_date`, matching the Python `ModelMetadata` schema generated from TypeSafe OpenAPI. A server that omits `description` fails `models()` and can still serve `system_one`.
- Default model `jev-latest` will 404 on a server that does not have that name. Callers must pass `model`.
- `x-typesafe-*` headers are always sent. A compatible server should ignore them.

## Change in this PR

1. `normalize_base_url` trims, strips trailing slashes, and rejects an empty or non-http(s) URL at `build`.
2. `tests/contract.rs` posts and lists models at `{mock}/gateway/v1/...` with a trailing slash on the base URL.
3. `examples/custom_base_url.rs` runs against wiremock. Live mode requires `TYPESAFE_BASE_URL` and does not fall back to TypeSafe.
4. README, `AGENTS.md`, and `examples/README.md` say how to point at another server.
5. `benches/client_overhead.rs`. No hot-path edit.

## Tradeoffs

| Option | Effect | Cost | Decision |
| --- | --- | --- | --- |
| Docs, example, validate base URL | Callers see `base_url` and fail fast on a bad one | Small diff | Done |
| Typed profile (`TypeSafe` vs `Custom`) | Names the same string | New API, no new behavior | Wait |
| Cargo feature for "generic System One" | Splits one client | Two builds of the same code | No |
| Optional auth scheme / strip `x-typesafe-*` | Helps a server that is not Bearer or that rejects unknown headers | Breaks Python parity | Wait for a server that needs it |
| Relax `ModelMetadata` fields | `models()` accepts a thinner JSON | Diverges from the OpenAPI schema | Wait |
| HTTP server in this crate | This process would implement System One | New product, not a client gap | No |
| Change redirect policy | Would surface 3xx instead of following | Breaks a same-origin 307 that today works | No |

## Redirects and TLS

**Measured** test `same_origin_307_is_followed`: `POST /v1/systemone` returns 307 to `/v1/systemone-landed` on the same mock. The client follows, the second body is still `{"state":"x",...}`, and `Authorization: Bearer test-key` is still present.

**Measured** by reading `reqwest` 0.11.27 `src/redirect.rs`: default limit is 10. `remove_sensitive_headers` drops `Authorization` when host or port changes. Not covered by a crate test.

**Measured** `Cargo.toml`: TLS backend is rustls. No custom-root API. `http_client` replaces the whole `reqwest` client, including redirect policy.

## Benchmarks

Command:

```bash
cargo bench --bench client_overhead
```

Harness: wiremock, retries off (`RetryPolicy::disabled()`), one `reqwest` client reused, tiny JSON. This is client serialize, localhost HTTP, and deserialize. It is not model latency. No `TYPESAFE_API_KEY`. No call to `https://api.typesafe.ai`.

Criterion 0.5.1, sample size 40, 5s measurement, release profile, this VM (`rustc` 1.98.1).

Baseline, client send path identical to `main` (bench added, `src/` not yet edited):

| Bench | Time |
| --- | --- |
| `mock_http/system_one` | 64.333 µs (63.895–64.717) |
| `mock_http/models` | 57.409 µs (56.901–57.921) |
| `client_build` | 17.698 µs (17.664–17.744) |

After `normalize_base_url` (build-time parse only; `Client::send` not edited):

| Bench | Time | Criterion vs baseline |
| --- | --- | --- |
| `mock_http/system_one` | 62.654 µs (62.351–63.060) | no change (p = 0.07) |
| `mock_http/models` | 66.736 µs, then a rerun at 54.747 µs | flagged a regression, then an improvement |
| `client_build` | 18.016 µs (17.956–18.085) | no change (p = 0.12) |

**Measured:** `models` moved by about 10 µs across three runs with no `models` code change. Treat that as mock-HTTP noise. **Inferred:** a clone or buffer tweak inside the client is smaller than this noise. No micro-optimization shipped.

`client_build` is about 18 µs and the call is about 60 µs. Reuse the `Client`. Building one per call is not the bottleneck on this mock.

## Improvements, ranked

1. Tell callers about `base_url`. Done in docs and `examples/custom_base_url.rs`.
2. Reject a bad base URL at `build`. Done.
3. Keep one client type. A profile enum adds nothing.
4. Leave redirects, TLS, Bearer, and `x-typesafe-*` headers as they are until a real server breaks.
5. Do not chase the 60 µs mock round trip.

## Wait for operator

- A server that needs a non-Bearer scheme or that rejects `x-typesafe-*`.
- A `models()` payload that omits `description` or `release_date`.
- A self-consistency example that actually repeats a noul.
- Deduping `is_live` and the blocking mock setup.
- Any HTTP server, OpenAI-shaped or System One-shaped, in this crate.
